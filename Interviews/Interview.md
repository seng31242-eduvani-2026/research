# Structured Interview – Vani Tuition Centre System


**Interview Date:** 23 May 2026  
**Duration:** 30–45 minutes  
**Participant:** Tuition Centre Administrator (Client)  
**Conducted By:** Group 4 team members  
**Purpose:** To gather functional and non-functional requirements for the Vani Tuition Centre System.

## 2. Interview Guide

The following structured questions were used during the interview.

### 2.1 Student Management

- How are student records currently managed?
- What student information should be stored?
- Who should have permission to manage student records?
- Should attendance and payment status be linked to student profiles?

### 2.2 Teacher Management

- What teacher information should the system maintain?
- How should teacher subject assignments be managed?
- Should teacher payment records be maintained?

### 2.3 Attendance Management

- How should attendance be recorded?
- Should QR code attendance be used?
- Who should receive attendance notifications?

### 2.4 Notification System

- What types of notifications should parents receive?
- Should overdue payment reminders be automated?
- Should general announcements and parent meeting notices be supported?

### 2.5 Assignment Management

- Should teachers upload assignments digitally?
- Should students submit assignments through the system?
- Should teachers review submissions within the system?

### 2.6 Marks Management

- How should marks be uploaded?
- Who should access student marks?
- Should parents be allowed to view marks?

### 2.7 AI Learning Support

- Should AI chatbot support be included?
- What type of learning resources should be uploaded?
- Should students ask subject-related questions using AI?

## 3. Interview Summary

The client explained that current tuition centre operations are mostly managed manually. This creates difficulties in maintaining student information, tracking attendance, monitoring payments, handling assignments, managing marks, and communicating with parents.

The client requested a centralised web-based solution capable of managing student records, teacher records, QR-based attendance, notifications, assignments, marks, payments, reports, and AI-powered learning assistance. The client particularly emphasised parent communication, attendance monitoring, and AI chatbot support for students.

## 4. Client Pain Points

| Pain Point | Description |
|---|---|
| Manual record keeping | Student and teacher records are maintained using paper-based methods, causing data loss and inefficiency. |
| Attendance tracking | Attendance is marked manually without a digital record, making reporting difficult. |
| Payment monitoring | There is no system to track payments or remind parents about overdue payments. |
| Parent communication | There is no automated notification mechanism for parent communication. |
| Assignment handling | Assignments are distributed and submitted physically without digital tracking. |
| Marks management | Marks are recorded in manual registers without secure digital storage or easy parent access. |
| Learning support | No AI-based or digital learning support is available for students. |
