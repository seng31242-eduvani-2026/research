# Contributing Guidelines

## Branch Strategy

### Main Branch

The `main` branch contains only approved research and analysis materials.

- Direct pushes to `main` are not allowed
- All changes must be merged through Pull Requests

---

### Draft Branches

Use the following naming convention for research branches:

```plaintext
draft/<research-topic>
```

---

### Fix Branches

Use the following naming convention for corrections:

```plaintext
fix/<issue-number>
```

---

## Contribution Workflow

1. Pull the latest changes from `main`
2. Create a new branch
3. Add or update research materials
4. Commit changes with meaningful messages
5. Push the branch to GitHub
6. Create a Pull Request
7. Wait for at least 1 approval
8. Merge into `main`

---

## Commit Message Convention

Use clear and meaningful commit messages.

### Format

```plaintext
<type>(<scope>): <description>
```

---

## Pull Request Rules

- PRs must be reviewed before merging
- At least 1 approval is required
- Resolve merge conflicts before merging
- Keep PR descriptions clear and concise

---

## Repository Rules

- Do not upload unnecessary files
- Maintain proper folder structure
- Keep research files properly categorized
- Verify sources before submission
- Follow version control practices properly
